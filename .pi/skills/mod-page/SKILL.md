# mod 说明页

属于苏丹的游戏 mod 工作区。没读过 `mod-creator` 的话，先读它。

## 这是什么

**需求讨论的载体。** 玩家对着一个页面，比对着一段 JSON 好说话：他能看见要做哪张卡、哪些字段取什么值、卡面拼出来什么效果、剧情分支按什么顺序走。你写页面，他给意见，你改方案。

**它是一个给玩家看的 HTML 页面，不是文档。** 页面上是方案本身——取值、结构、卡面合成结果——不是「我做了什么」的说明。

**它可以出现在写配置记录之前，也可以之后。** 两种来源：

| 来源 | 命令 | 写盘吗 |
|---|---|---|
| 提案：还没写进 mod | `node tools/page.mjs card --mod your_mods/<ModName> --id <卡 id> --spec - < 提案.json` | **不写**，页面副标题会标「提案 · 尚未写入 mod」 |
| 已写进 mod 的记录 | `node tools/page.mjs card --mod your_mods/<ModName> --id <卡 id>` | 不写，只读 |

提案走 `--spec -` 从标准输入读 JSON；也可以给 `--spec <文件>`。写进 mod 的记录直接读 `your_mods/<ModName>/config/`，读不到就打 `FAIL  no <kind> <id> in this mod`，并提示可以用 `--spec` 先看提案。

**提案只做 JSON 解析，不做字段校验。** 键名对不对、值合不合法，要等写进 mod 之后跑 `node tools/lint.mjs` 才知道。所以提案阶段只能保证「结构能渲染」，不能保证「游戏会读」。

**每次运行都按当前记录重新渲染整份文件。** 同一个 `--out` 会被整份覆盖，不只是你手改过的地方。所以要改内容就改记录再重跑；要改版式改 `tools/page.mjs`，要改颜色字号改 `tools/html.mjs` 的 `CSS`（全仓页面共用那一份）。

**这个 HTML 页面是只读的，意见在聊天里回。** 苏丹仓没有配页面编辑器，页面上的控件收不到任何值，所以 `page.mjs` 只印文字。

## 什么时候写页面

**写页面，不要把选项摊在一段长回复里再问。**

下面任一条成立就写页面：

- 你们必须先就范围或某个值达成一致，然后才能开始写 mod。
- 玩家要改**剧情文字**：事件叙事、选项按钮、结算提示、仪式与卡面的文案。文字要读起来对味，光看 JSON 里的字符串判断不了。
- 玩家问这个 mod 做了什么，或者这次改了什么。
- 结论需要数字、选项或对比才说得清。
- 玩家说做得单薄、含糊、不完整。

一句话就能答的问题，直接回复就够。

## `ModName` 还没定？

先调 `create_mod_folder(name="<小写 snake_case，字母开头，≤40>")` 建目录并绑定会话，然后写 `info.json`。它只建目录、不建源文件。

名字规则、`info.json` 的字段与失败码，都在 `mod-creator` → `## Mod layout` 与 `## info.json` 两节。

## 页面放在哪

```
your_mods/<ModName>/.preview/<主题>.modpage.html
```

- 用 `node tools/page.mjs card --mod your_mods/<ModName> --id <卡 id>` 生成，`rite`、`event` 同理；还没写进 mod 的提案加上 `--spec -`。默认就写到这个路径，文件名按内容起。
- 页面是**只读**的：值都印成文字，没有输入框。卡页面还会把卡面拼出来给你看（原版底板 + 卡图 + 卡名），合成图直接内嵌。
- `.preview/` 不属于 mod：它被 git 忽略，也不要装进游戏。
- 后缀 `.modpage.html` 只是 `tools/page.mjs` 的默认命名，**不是必需**：现在没有编辑器按后缀匹配，改成 `.html` 一样能打开。沿用默认值即可，别在别处依赖这个后缀。

## 页面里有什么（由脚本决定，你不用排版）

`tools/page.mjs` 按记录类型生成固定的版式。你要做的是把记录写对，不是画页面。

| 类型 | 页面里出现的东西 |
|---|---|
| 卡 | 卡面合成图（原版底板 + 卡图 + 卡名）；名字、副标题、类别、稀有度、说明、可装备槽、是否唯一；画面主体（`composeSubject` 的结果）；标记表（有/无）；数值表（标签对整数 + 原版范围） |
| 仪式 | 名字、地点、持续回合、说明；槽位表（提示文字、只接受什么、必填还是可空）；结算分支列表，每条带条件与结果 |
| 事件 | 备注明、触发、条件、是否可重复、启动是否即检查；结算分支列表 |

所以「写什么」这一点已经解决了：页面上看到的 `name`、`title`、`text`、`type`、`rare`、`tag` 数字、分支顺序，全是记录里的值。**玩家对 `tag` 数字和分支顺序有意见**，因为那是平衡与设计。

## 要对比几个方案

页面只显示**一条**记录。要比方案，就各生成一个提案页，文件名区分开：

```
node tools/page.mjs card --mod your_mods/<ModName> --id <卡 id> --spec - --out your_mods/<ModName>/.preview/a-方案一.html  < 方案一.json
node tools/page.mjs card --mod your_mods/<ModName> --id <卡 id> --spec - --out your_mods/<ModName>/.preview/a-方案二.html  < 方案二.json
```

然后把两个路径都给玩家，并说清你推荐哪个、为什么。**不要**在回复里把两套 JSON 全文贴出来。

## 样式

页面要读起来像游戏的一部分，不像一份文档。游戏界面是深暖棕底、羊皮纸面板、金色分隔线、带刻线的装饰。

**不要自己编颜色值。** 色板已经在 `tools/html.mjs` 的 `CSS` 里（`--paper` 底、`--panel` 面板、`--rule` 分隔线、`--gold` 标题、`--ink` 正文、`--dim` 次要），页面默认就用它。要加新组件就复用这些变量，不要引入第二套色板。

标题用衬线体，正文用系统无衬线体。正文栏要窄——面板本来就不宽。

## 玩家回话之后

1. 按玩家说的改**记录**（或 `--spec` 里的提案 JSON）。
2. 用同一个 `--out` 重新生成页面，页面就更新了。
3. 把新页面的路径再给玩家一次，说明这次改了哪几处。

玩家说「不对」而你认为原值有理由时，不要用文字反复解释：**各生成一页**（原方案与他的方案，用 `--out` 区分），让他直接比较两页的差别。
