# 苏丹的提示词写作标准（中文为主）

本文件规定本仓里所有会进 agent 上下文的字该怎么写。判据来自简化技术中文（`ste` skill）与本项目已经用开的中文。

放在 `script/` 而不是文档目录：它是**维护者的判据**，和 `run-tests.mjs`、`check-terms.mjs` 一起被读写，不是给玩家看的说明。

**适用对象**：`AGENTS.md` 与四份 `SKILL.md`。改这些文件前必须先读本文件。

上级：[`../AGENTS.md`](../AGENTS.md)。相关：[`../schema/SCHEMA.md`](../schema/SCHEMA.md)（生成物，键与值的权威表）；字段普查在设计仓 `desktop-gamer-agent-pi/docs/sudan-game/fields/`（本仓之外，按路径引用，不建链接）；另外两份标准在设计仓 `docs/eu5-harness/prompt-standard.md`（EU5 全英文，不能照抄）与 `docs/duckov-harness/prompt-standard.md`（duckov 版，骨架相同、术语表不同）。

## 1. 为什么苏丹单独一份

1. **游戏自己的注释是中文。** `//时机`（1272 处）、`//是否可以重复触发`（1271 处）、`//不能为空`（53 处）、`//必新`。这些是玩家和策划的原话，我们的文档没有理由比游戏更英文化。
2. **页面已经有一套管用的中文。** 故事图用「时机 / 条件 / 结果 / 槽位 / 先结算 / 正常结算 / 附加结算 / 后日谈 / 周期 / 地点 / 计数器 / 吸附槽」。文档必须用同一批词，否则 agent 在页面和 SKILL 之间看到两套说法。
3. EU5 那份标准是全英文的，判据不同；duckov 那份覆盖「中文为主 + 英文工具面」，与本文件的骨架相同，**但术语表各自独立**（游戏不同）。

## 2. 适用范围

**中文**（本文件是它们的判据）：

| 文件 | 说明 |
|---|---|
| `AGENTS.md` | 仓级规则 |
| `.pi/skills/mod-creator/SKILL.md` | 写 mod 的主参考，最大一份 |
| `.pi/skills/card-art/SKILL.md` | 卡图 |
| `.pi/skills/mod-installer/SKILL.md` | 安装与读日志 |
| `.pi/skills/mod-page/SKILL.md` | 给玩家看的数据页 |

**英文**（工具面，不译）：

1. 工具的 stdout/stderr 与 `content` 返回文案、错误文案。
2. 规则码（`UNKNOWN_FIELD`、`LEGACY_FIELD`、`EVENT_BRANCH_CONDITION`）与状态词（`RESULT: PASS`）。
3. 配置键名、枚举值、文件路径、游戏日志原文、命令。

**不适用**（本轮不动）：

| 对象 | 理由 |
|---|---|
| `schema/SCHEMA.md` | **生成物**。它的散文在 `tools/gen-schema-doc.mjs` 里；只手改 SCHEMA.md 会在下一次 `--check` 时变回英文。要翻得连着翻生成器，另开一轮 |
| `schema/i18n.md` | 讲**游戏**怎么翻译自己的文字，与我们的写作语言无关；需要时单独定 |
| `reference/**` | Unity 官方示例原文 |
| `THIRD_PARTY_LICENSES.md` | 法务原文 |
| `your_mods/**` 的配置与 `schema/field-switches.json` | 这些是**游戏/页面的数据**，不是提示词；其中的中文是给玩家看的 |
| 代码、代码注释、commit message | 按 `ste` skill 的排除项办；但工具里的 `content`/错误**字符串**属于上面的英文清单 |

## 3. 语言分界

同一条事实在三个位置有三种写法，不混用：

| 位置 | 语言 | 例子 |
|---|---|---|
| 工具**输出** | 只英文 + ASCII（Windows GBK 会乱码） | `0 fail, 3 warn, 1 info` / `RESULT: PASS` / `UNKNOWN_TIMING` |
| 文档**引用**输出 | 原样英文，不译、不改编 | 「跑完看到 `RESULT: PASS` 就说明没有 FAIL」 |
| 文档**叙述**机制 | 中文 | 「`settlement_extre` 逐条看自己的 `condition`，成立就执行」 |

**判据**：能在代码里 grep 到的东西保持英文；剩下的用中文。

## 4. 中文规则

### 4.1 一词一义

一个概念只用一个词，不许同义轮换。术语见 §5。破坏它的典型写法是把「结算分支」写成「结果分支」「结算支线」「分支项」轮着来。

### 4.2 一句一事

一句话只说一件事。超过 40 字的句子拆开。条件、例外、后果各占一句。

### 4.3 主语写全，不靠指代

把名词再写一遍，不要用「它」「那个」「上面说的」「前一条」去指。中文句子省主语读起来顺，但省掉的那个词是**唯一能定位事实的东西**——换个位置读就丢了。

- 差：「玩家禁用它，原版回来。」
- 好：「玩家禁用这个 mod 之后，游戏重新读原版文件，原版内容恢复。」

### 4.4 条件在前

先写触发条件，再写后果。中文读者和 agent 都按这个顺序解析：

- 好：「`condition` 里写多个键时，它们必须**全部**成立。」
- 差：「它们必须全部成立，如果你在 `condition` 里写多个键。」

### 4.5 键名与字面量

1. 键名、枚举值、错误码、路径、命令**一律英文**，并用反引号包起来：`` `settlement_prior` ``、`` `char` ``、`` `UNKNOWN_FIELD` ``。
2. 中文括注只在该文档**首次出现**时给一次：`` `settlement_prior`（先结算） ``。后文只写键名。
3. 指**键**时写反引号英文；指**机制**时写中文。这条是唯一的歧义分界线：
   - 「`condition` 成立」= 那个键求值为真
   - 「条件写错了」= 机制层面说错
4. 代码块里**只允许 ASCII 标点**（引号、冒号、逗号、括号）。中文只出现在 `//` 注释里。否则复制出去就是语法错误。
5. 引用的游戏日志、命令、报错原文一字不改。

### 4.6 符号

1. 表格用于枚举，列表用于步骤。同一层里不混用。
2. 警告用「注意：」起头，不用 emoji 装饰正文。
3. 数字与英文两侧不加空格，与仓库现有文档一致（`写 mod`、`0 条`）。

### 4.7 段与列表

1. 一段不超过 5 行。
2. 列表项以动词或名词开头，不用「- 这个……」「- 那个……」。
3. 不给开放式列举。列表说清「还有哪些类别」而不是「等等」。

### 5.3 C 阶段词（做 mod 的七步，每一步只有一个名字）

同一个动作在我们文档里叫过好几个名字：「写 config」「制作 mod」「写 json」。这些说法互相不重合，agent 会按字面理解错。**做 mod 的流程固定七步，每一步只用一个词。**

<!-- terms:stages:begin -->
| 阶段词 | 含义 | 禁写 |
|---|---|---|
| 建 mod 骨架 | 建 `your_mods/<ModName>/` 与 `info.json` | 建工程、初始化 |
| 写配置记录 | 在 `config/` 下新增或修改记录：表条目（`config/cards.json` 里的一个 id）或整份文件（`config/event/<id>.json`） | 写 config、改 config、写 json、配置 |
| 放资源 | 往 `image/`、`bgm/` 放文件 | 导素材 |
| 校验 | 跑 `node tools/lint.mjs` 看它报什么 | — |
| 安装 | 把 mod 目录复制到 mod 根目录 | 部署、上线 |
| 启用 | 玩家在游戏内的 mod 面板里勾选这个 mod | 激活、开启 |
| 验收 | 读日志，再让玩家在游戏里看 | — |
<!-- terms:stages:end -->

「制作 mod」只用来指**整条流程**（七步全做）。要说某一步，就写那一步的名字。

三个容易混的词各有各的活：**校验**是跑 lint 看规则，**验收**是读日志加游戏里看，**测试**是 `node --test` 跑 `script/*.test.mjs`。不要互相顶替。

### 5.4 D 状态词与结论词

1. `PASS`、`WARN`、`FAIL` 是工具输出，**不译**，也不在文档里造中文对应。
2. 我们自己的结论用中文：已验证、未决、死键、收益、回归、有意保留。
3. 判断有没有做完，写「证据」而不是「应该没问题」。

## 6. 检查方法

### 6.1 机检

`script/check-terms.mjs` 读本文件的 A、B 两块，查三件事：

1. **键名在反引号里**：A 块的键出现在中文文件里而没被反引号包住 → 报错。
2. **禁用词**：B 块的禁写列命中 → 报错，并给出该用哪个词。
3. **工具输出是 ASCII**：`tools/*.mjs` 里 `fail(` / `warn(` / `info(` 的消息不含非 ASCII 字符（Windows GBK 会乱码）。

```bash
node script/check-terms.mjs
node script/check-terms.mjs --standard <path>   # 默认读本仓的同级目录
```

退出码非零即有违规。它由 `script/terms.test.mjs` 带进 `script/run-tests.mjs`，和其他套件一起跑。

**尚未翻译的文件算「待办」，不算违规。** 汉字占非空白字符不到 5% 的文件会被列为 `pending` 并打印出来，但不让测试变红；`--strict` 把它变成失败——翻完最后一份时用这个开关收口。这样是为了避免「还没开工就先红」，红久了的检查没人看。

### 6.2 人工核对

机检查不出下面这些，逐条过：

1. 首次出现的键是否给了中文括注，后文是否只写键名。
2. 同一个概念有没有换过说法。
3. 代码块里有没有非 ASCII 标点。
4. 引用的日志、命令、报错是否一字未改。
5. 每一句是否只说一件事，条件是否在前。
